Study 1 · Reduced Contact Model · Project Chrono → NeDM

Can a learned contact encoder replace collision detection in a neural simulator?

A rigid box is dropped onto a plane in Project Chrono. A small network learns to reproduce Chrono's contact reports from geometry and pose alone; a recurrent NeDM transition model then predicts the motion from those contacts. On box sizes never seen in training, the learned contacts drive the frozen dynamics model as well as exact contacts do.

Overview

Two modules, one auditable interface

Conventional simulators separate collision detection (geometry → contact manifold) from the solver (contact manifold + state → next state). ContactROM keeps that split but learns the first half. The interface between the two is an explicit, checkable set of contact tokens rather than a hidden latent, so each module can be validated on its own before they are connected.

Study 1 uses the simplest scene that exercises impacts, rebounds and resting contact — a box on a plane — so that every prediction can be compared against closed-form geometry and against Chrono's own records.

Hypotheses. H1: contact information improves NeDM's impact prediction. H2: that information can be learned from geometry and pose. H3: explicit quantities plus a learned latent beat either alone. H4: the encoder generalizes to unseen box dimensions.

Data collection

Recording Chrono's contact manifold, step by step

Scene and physics

One dynamic box (uniform density 1000 kg/m³, inertia recomputed from its dimensions) is released with zero velocity above a fixed ground block whose top face is z = 0. Everything that affects the physics is frozen for the whole study and stored with every episode so that any episode can be replayed exactly.

What is recorded each step

  • State before the step: position, orientation quaternion (w, x, y, z, canonical sign), linear velocity, angular velocity (world and body frame), settled flag.
  • Raw Chrono contacts from ReportAllContacts: both contact points, the contact frame (X axis = normal), signed distance, effective radius, reaction force and torque in the contact frame, body identities, NSC constraint offset. Up to 8 records per frame are kept; overflow is counted, never dropped.
  • Canonical view derived from the raw records: box = A, ground = B, normal pointing ground → box, distance > 0 separated / < 0 penetrating, box-side point clamped to the true half-extents, ground point projected along the normal, padded to 4 slots with a mask, plus per-frame contact count, mode (none / corner / edge / face) and the analytic corner gaps.
  • Events per episode: first-impact step, contact runs, rebound intervals, settle step, maximum penetration.

Time alignment

Contacts read after DoStepDynamics(k) come from the collision pass at the start of step k, i.e. from the pre-step pose — verified: the reported distance equals the analytic corner-to-plane gap of that pose. Every learning record is therefore (statek, contactsk) → statek+1.

Settling

A box resting on four NSC contacts shows a deterministic rocking limit cycle (|v| ≈ 3 mm/s, |ω| ≈ 0.08 rad/s, ±7 µm penetration, zero drift), so settling is detected from pose change over a 200-step window instead of velocity thresholds. 1 720 of the 2 000 pilot episodes settle before 2 s.

Validation that every set passes

Free flight

Pre-impact trajectory matches ballistics: velocity error 1e-13 m/s; position offset ≤ 2.7 mm, exactly the first-order lag of Chrono's semi-implicit Euler.

First-contact timing

First reported contact lies within one step of the analytic crossing of the proximity margin (median 0.26, max 0.91 steps).

Replay & leakage

Re-simulating an episode from its stored configuration reproduces states and contacts with 0.0 difference; no episode or geometry group appears in two splits.

Two Chrono behaviors had to be pinned down before the labels were trustworthy. SetCollisionSystemType silently resets the collision envelope to 30 mm, so it is set afterwards and asserted per body. Bullet reports the box-side contact point on an envelope-inflated shape (1 mm outward laterally, exact along the normal); the canonical labels clamp that point back onto the true box, while the raw record is kept untouched. Alternative pairings were tested and rejected: a triangle-mesh ground produces wrong normals on edges and a convex-hull box produces wrong points.

Model training

A set-valued contact encoder and a NeDM-compatible transition model

Contact encoder

Input: the box half-extents, its pose, and a cached surface representation of the box. No velocities — contact geometry must follow from pose alone. Tokens are expressed in a frame with world axes and origin at the box center projected onto the ground, which makes the prediction exactly invariant to sliding the box sideways.

Two surface representations were trained with identical decoders:

  • Patch encoder — the 12 triangular faces of the box as tokens (vertices, centroid, normal, area, neighbor normals, dihedral/sharp-edge flags), a shared MLP, three message-passing layers over face adjacency. This is the representation meant to extend to arbitrary meshes.
  • Point encoder — 152 surface samples (8 corners, 48 edge points, 96 face points) with normals and a corner/edge/face tag, a shared MLP and one kNN (k = 16) local-aggregation block, PointNet++-style.
  • Analytic baseline — closed-form corner-to-plane geometry in the same output format; the correctness reference.

Output: four unordered slots, each with an on/off logit, the contact point on the box (constrained inside the box), the matching ground point, a unit normal, the signed distance, a 16-d learned latent and a log-variance; plus a 0–4 cardinality head. Slots are decoded by four learned queries that cross-attend over the surface tokens (2 layers, 4 heads, 128-d).

Loss: Hungarian matching of predicted slots to Chrono's contacts, then focal cross-entropy for activation, Huber on distance, L1 on both points (normalized by the smallest half-extent), cosine on normals, cross-entropy on the count, and a Gaussian likelihood for the uncertainty (log-variance bounded to keep it finite). Frames are sampled balanced across six regimes — far free flight, near-contact, first impact, in contact, rebound / re-impact, resting — otherwise 60 % of frames are free flight and "no contact" wins.

Transition model (NeDM)

A causal continuous-token transformer, the same design as NeDM's dynamics model: the last 32 steps of state (position, quaternion, velocities) and box size are embedded, 3 layers × 4 heads × 128-d, and the head predicts the change in velocity and angular velocity. Two exact facts of Chrono's integrator are built in: the free-flight velocity change (−g·dt) is a fixed prior the network only corrects, and position / orientation are integrated with Chrono's own semi-implicit rule (verified to 1e-15 on the data), so quaternions never drift off the unit sphere.

Contact tokens enter through a permutation-invariant adapter: per slot, the distance, normal, box point, lever arm and the relative velocity it implies (normal and tangential) go through a shared MLP, are masked by the slot's activation, sum- and max-pooled, and appended to the state token. A contact gate multiplies the network's correction by "any contact active" — exact for Chrono, where a step with no reported contact is pure free flight.

Trained with mean-squared error on normalized deltas over windows, oversampling windows that contain impacts (×4). Closed-loop evaluation primes with 32 true steps and then runs autonomously to the end of the episode, with contacts supplied by one of three sources: recorded (replayed open-loop), analytic (recomputed from the predicted pose), or the learned encoder.

Experiments

A

State-only NeDM — the baseline it must beat.

B

Oracle-contact NeDM — Chrono's contacts as input; the upper bound the interface allows.

C

Contact encoders alone, geometry held out — selects the representation.

D

Learned contacts fed to the frozen model from B — attributes any degradation to the encoder.

E

Joint fine-tuning with an 8-step unrolled loss, the explicit contact loss retained so the latent cannot stop encoding geometry.

Compute

All runs used single GPUs on the Euler cluster with SLURM dependency chains (data generation → C ∥ A/B → D, E → summary). Encoders: 8 000 steps ≈ 10 – 23 min, 30 000 steps ≈ 19 – 30 min (batch 512, CPU Hungarian matching is the bottleneck). Transition models: 30 000 steps ≈ 6 – 16 min including rollouts. Joint fine-tuning: 66 – 73 min for 8 000 steps; the point encoder's kNN block needs ~2.5 MB per frame, so joint training uses batch 32 and chunked evaluation.

Two findings that changed the outcome

The reporting boundary is the whole difficulty

Encoders trained for 8 000 steps had zero false positives in free flight and perfect recall at rest, yet only ~50 % recall on first-impact frames: the ~3 mm threshold at which Chrono starts reporting is a sharp boundary that needs sub-millimetre resolution. With that encoder, the frozen model failed outright (impact error back to 3.5 m/s). Training 3.75× longer fixed it without any architectural change.

Gate the impulse with a hard mask

An early evaluation gated the transition model's correction with the encoder's activation probability. A model trained on hard 0/1 activations then under-applied impulses at uncertain first-impact frames (error 2 – 3 m/s). Using the thresholded mask — the same signal the model saw in training — restored oracle-level results. Soft gating is only consistent for jointly trained models.

Limitations & next steps

What this study does not yet show

  • Long-horizon orientation. At the end of the 2 s episodes every model, the oracle included, has 80 – 95° of orientation error: the settling / rocking phase drifts. A per-regime analysis of that phase is the first open item.
  • Near-contact recall sits at 99.2 % against a 99.5 % target; threshold calibration or more boundary data should close it.
  • H3 is only partially tested: explicit + latent beat explicit-only when the encoder was weak, not when it was strong; a latent-only ablation has not been run.
  • Scope: one box, one plane, one solver (NSC), fixed material, zero initial velocity. The neural-SDF baseline, Phase 1C (initial twist, material variation) and multi-body scenes are future work.

The analytic baseline is faster and more accurate than either network — as expected, and by design its role is a correctness reference, not a competitor. The claim this study supports is narrower and, for the program, more important: the explicit contact-token interface is sufficient for a recurrent neural simulator, and it can be produced by a small geometry-conditioned network that generalizes across box dimensions.

The next milestone from the plan is the geometry bake-off on non-box shapes, where the patch (mesh) representation is expected to matter and the point representation to need denser sampling.

Reproduce

Everything regenerates from configs and seeds

conda create -n recom python=3.12 -y && conda activate recom
conda install projectchrono::pychrono -c conda-forge -y
pip install torch numpy scipy pyarrow pyyaml tqdm matplotlib pytest tensorboard
python -m pytest tests -q                       # 28 passed

python scripts/generate_dataset.py configs/pilot1b.yaml
python scripts/validate_dataset.py data/pilot1b --replay 3

# encoders (Experiment C)
python scripts/train_contact.py --data data/pilot1b --encoder point --steps 30000 --out runs/expC_point_30k
# transition models (A / B), then D and E
python scripts/train_transition.py --data data/pilot1b --contact-mode none     --out runs/expA
python scripts/train_transition.py --data data/pilot1b --contact-mode explicit --out runs/expB \
    --eval-contact-sources gt,analytic
python scripts/train_transition.py --data data/pilot1b --contact-mode explicit --out runs/expD \
    --eval-only runs/expB/final.pt --encoder-ckpt runs/expC_point_30k/final.pt \
    --eval-contact-sources analytic,learned
python scripts/summarize_runs.py runs

On the Euler cluster the same steps are wrapped as SLURM jobs (cluster/submit_all.sh, cluster/submit_round2.sh) with module load conda/miniforge && bootstrap-conda. Per-run metrics, training curves and logs for every experiment on this page are committed under results/cluster_2026-08-26/; the running log of decisions and numbers is docs/PROGRESS.md.

The repository also exports datasets in NeDM's CSV / dataset_index.json layout (recom/data/nedm_export.py) so the contact block can be trained inside the original NeDM pipeline as action_fields, without changes to that code.
